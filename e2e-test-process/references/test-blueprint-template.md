# 测试蓝图模板

> 蓝图的唯一目的：在写用例之前，用最短篇幅回答「这次到底测什么、不测什么、有没有重复」。
> 它不写执行命令、不写断言细节——那是 `test-case-spec.md` 的事。
> 模板中的表名、topic、接口、配置 key 仅示意格式；实际取值以被测仓库的 `.claude/auto-test-profile.md` 与项目 skill 的执行载体声明为准。

## 何时产出

S2 阶段。输入是需求文档 / 接口文档 / 技术方案 / 分支提交历史（S1 阶段）。

**蓝图确认前不要写用例、不要造数据、不要执行。** 蓝图的价值就在于把返工挡在这一步。

## 模板

文件：`<repo>/docs/auto-test/<需求名>-<YYYYMMDD>/<需求名>-test-blueprint.md`

```markdown
# <需求名> 测试蓝图

- 需求来源：<PRD 链接 / 文档路径>
- 分支 / commit：<branch> @ <commit>
- 测试环境：<env>，载体：<部署 / 本地启动 / CLI>
- 编写日期：YYYY-MM-DD

## 1. 验收点（REQ）

| ID | 验收点 | 来源 | 优先级 |
|---|---|---|---|
| REQ-1 | 买家评级 A 保存标签后应生成接管信号 | PRD 3.2 | P0 |
| REQ-2 | 评分成功后消息体应包含 product1/product2/product | 接口文档 §4 | P0 |
| REQ-3 | 已通知的买家不重复生成信号 | PRD 3.4 | P1 |

> 验收点用「系统应……」的断言句式，一条只描述一个可判定的结果。
> 来源必须可指回具体章节；没有来源的自行扩展不算验收点。

## 3. 测试点候选

按维度铺开，每行一个候选点。允许先多后少，靠 §5 去重收敛。

| ID | 测试点 | 维度 | 对应 REQ |
|---|---|---|---|
| BLP-01 | 评级 A + categories 非空 → 生成信号 | 主流程 | REQ-1 |
| BLP-02 | 评级 C → 不生成信号 | 分支 | REQ-1 |
| BLP-03 | 评分接口不可达 → fail-open 仍发消息 | 异常/降级 | REQ-2 |

| BLP-06 | 消息体缺商品时对应键不出现 | 边界 | REQ-2 |

维度参考（不是每条都要覆盖，按需求取舍）：主流程 / 分支条件 / 异步与线程池 / 外部依赖失败 / 落库 / 消息 / 幂等 / 边界值 / 配置开关 / 跨仓 / 并发。

如果变更涉及 `@Scheduled` 或 Quartz 调度，在影响面 §2 的「调度」行写清 cron、开关与手动触发入口，并补「重复触发不重复处理」的测试点。

## 4. 不测范围

| 不测内容 | 理由 | 承接方 |
|---|---|---|
| 评分模型准确率 | 模型侧需求，非本次改动 | 算法团队 |
| 历史存量信号回刷 | 本次不涉及数据迁移 | — |
| 高并发压测 | 单条验证，无容量目标 | 性能专项 |

> 不测范围必须写明理由。空白不等于默认不测。

## 6. 去重检查

逐条回答，答案是「否」才允许保留：

| 检查项 | 结论 |
|---|---|
| 是否有两条用例的验证目标完全一致？ | 否 |
| 是否有用例只是换了测试数据、步骤与预期都相同？ | 是（已合并为 TC-001 的参数表） |
| 是否有用例的预期包含在另一条用例的预期里？ | 否 |
| 是否有用例没有对应 REQ？ | 否 |
| 是否有 REQ 没有任何用例覆盖？ | REQ-4 待补 → 见 §7 |

合并规则：

- **同一验证目标 + 相同步骤 + 仅数据不同** → 合并为一条，用数据表列多组输入；
- **结果出口不同**（命中 / 未命中、成功 / 拦截）→ 必须拆条，不能写成「如果……则……」；
- **一条用例出现两个「然后」** → 拆。
```

## 合格蓝图的门槛

一份蓝图可以直接进入用例设计，当且仅当：

- [ ] 每个验收点都有唯一 ID、来源和可判定描述；
- [ ] 变更影响面覆盖了代码 diff 中出现的接口、表、topic、配置和调度；
- [ ] 测试点候选能覆盖全部 P0 验收点；
- [ ] 不测范围写明了理由；
- [ ] 去重检查结论为「无重复」或已合并；
- [ ] 待确认问题不阻塞 P0 执行；
- [ ] 需要新增的测试专用接口已列草案（§7.1）并获用户确认，开关默认关闭；
- [ ] 用户已确认骨架。

## 常见问题

| 问题 | 后果 | 修正 |
|---|---|---|
| 蓝图直接写出 curl 命令 | 混入执行细节，骨架看不清 | 命令放用例 |
| 测试点按「接口」「日志」分层列举 | 同一验证目标重复出现 | 按业务维度列，取证层放到用例 |
| 只列正向路径 | 缺陷集中在异常和配置分支时测不出来 | 对照变更影响面补分支与配置 |
| 不写不测范围 | 报告无法说明覆盖边界 | 显式列出并给理由 |
| 用例骨架没有 REQ 列 | 无法做覆盖矩阵 | 补上 REQ 映射 |
| 为造数据临时加生产可达的接口 | 线上污染风险 | 按 §7.1 出草案、用户确认，开关默认关闭 |
