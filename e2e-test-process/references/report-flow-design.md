# 测试流程图（`cases[].flow`）设计与排版约定

> 归属：`references/render-report.mjs` 的配套设计说明。数据字段以 `test-report-schema.md` 为准，
> 本文件只回答「为什么这样画、怎么改不会画坏」。改渲染器前先读本文件。

## 1. 定位

流程图是用例级**可选**字段：Markdown 仍是事实源，`flow` 只是把「这条用例怎么跑出来的」画成图，
HTML 里按节点组织的原始证据是它的下钻目标。没有 `flow` 的用例走旧路径，DOM 与告警完全不变。

## 2. 布局：横向蛇形折行（LR）

1. **分层**：Kahn 拓扑排序 + 最长路径分层，回边先被剥离（回边单独画，并触发 `FLOW_CYCLE_BACKEDGE`）。
   一层 = 一列，同层节点按声明顺序纵向堆叠，声明顺序即主分支优先。
2. **打包**：列按序贪心装入一行，累计宽度超过 `FLOW.ROW_MAX` 就换行。
3. **反向**：偶数行左→右，**奇数行右→左**（层号仍递增，只是从行右缘往左摆）。
   这样行尾总落在同一侧，跨行只需一段短通道，不必从行尾横穿回行首。
4. **居中**：行内各列按最大行宽对齐，同列节点在列高内垂直居中。

`direction: "TB"` 仍可用（纵向、每层一行），只作为长链兜底；默认与推荐值都是 `LR`。

## 3. 可读性基线（这一节是「字太小」问题的正解）

SVG 通过 `viewBox` **等比铺满容器**：

```css
.flow-svg { width: 100%; min-width: 520px; max-width: 1080px; height: auto; }
```

因此**实际字号 = `FLOW.FONT` ×（容器宽度 ÷ viewBox 宽度）**。节点宽度由文字宽度推导，
放大 `FLOW.FONT` 会让 viewBox 同步变宽、放大倍数同步变小，**净效果约等于零**。
真正决定字号的旋钮只有一个：**`FLOW.ROW_MAX`**。

| 旋钮 | 调小的效果 | 代价 |
| --- | --- | --- |
| `ROW_MAX` | 每行节点更少 → viewBox 更窄 → 放大倍数更大 → 字更大 | 折行更多、图更高 |
| `FONT` / `LINE_H` | 基本无净效果（见上） | 只影响换行位置与行高比例 |

当前基线（2026-11 定稿）：`ROW_MAX: 660`，1280 宽窗口下 10 节点用例约 1.35 倍放大，
正文 14px 的页面上图内标题实测 ≈ 17px。**验收口径：图内标题不小于正文字号，且不产生页面级横向滚动。**
窄屏由 `min-width: 520px` 兜底——宁可卡片内部横向滚动，也不把字缩到看不清。

改任一字号常量后，必须同步：`flowNodeSize()` 的行高、随 payload 下发的 `flowMetrics`
（客户端 `FM` 用它做基线与副标题偏移，避免客户端再抄一份常量）、以及 `.fl-title` / `.fl-sub` /
`.fl-edge-label` 的 CSS 字号；三者不同步会出现文字溢出或压线。

## 4. 节点形状与语义色

| type | 形状 | 语义 |
| --- | --- | --- |
| `start` / `end` | 胶囊 | 用例起止 |
| `http` | 圆角矩形 | 被测接口 / 测试脚本发出的请求 |
| `sql` | 圆柱 | 数据表查询或写入 |
| `schedule` | 六边形 | 调度注册 / 触发（Quartz、Job、Trigger） |
| `service` | 圆角矩形 | 服务端内部逻辑（默认回退类型） |
| `decision` | 菱形 | 分支判定，出边带 `label`（是/否/存在/不存在…） |
| `callback` | 平行四边形 | 下游回调 / 被调方 |
| `config` | 折角 | 配置中心读写（Apollo 等） |
| `log` | 文档波浪底 | 服务端日志 |
| `metric` | 旗标 | 指标 |
| `mq` | 尾部圆角矩形 | 消息 |
| `missing` | 圆角矩形（虚线） | 显式「未取证」占位 |

未知类型回退为 `service` 并触发 `FLOW_NODE_UNKNOWN_TYPE`。

## 5. 边与标签

- `kind`：`normal`（默认）/ `success` / `error` / `retry` / `async`，只影响线条颜色与虚实。
- 路由：同行走水平直线或三次贝塞尔（两端错位时）；同一列上下相邻走垂直线；
  跨行走「节点边缘 → 行间通道中线 → 目标」，圆角正交折线。
- 标签是**不透明胶囊**（`rect.fl-edge-label-bg` + 0.75px 描边），宽度由服务端按 `LABEL_FONT` 预计算，
  客户端不重新量文本。决策节点之后的层间距用 `GAP_DEC`（64）而非 `GAP`（34），
  避免分支标签压住目标节点角标；间距仍不够时**去掉该边的 label**，不要缩字号。

## 6. 证据挂载与未取证

- 证据只通过 `nodes[].evidenceRefs` 挂载，`evidence[]` 结构不变；一条证据可被多个节点引用
  （第二处显示「引用 ev-xxx」）。未被任何节点引用的证据归入「未挂载到流程节点的证据」，数据不丢。
- 角标①显示该节点的证据条数，点击节点展开并滚动到对应 `<details data-node>`。
- **设计上就没有证据的步骤**（服务端日志、异步链路的中间态）：标 `unverified: true` + `note` 说明原因，
  渲染为虚线描边 + 黄色「未取证」角标。**不允许伪造 payload 来消除虚线**。
- `start` / `end` / `decision` / `missing` 天然不产生证据，不触发 `FLOW_NODE_NO_EVIDENCE`。

## 7. 建模约定

- **重试不用回边**：按真实时序画前向链（首次回调 → 判断 → 置失败态 → 排重试 → 重试触发 → 重试回调 → 成功）。
  回边会让读者以为重试是同步循环，且会触发告警。
- **一条用例一张图**：只画该用例验证的主链路；跑一次通用前置流程不画。
- 节点 `label` 写业务语义（中文动词短语），`detail` 写可定位的技术标识（接口路径、表名、JobKey）。
  两者都不要超过 2 行——超出会被截断，全文只在 `<title>` 里。

## 8. 回归方式

```bash
# 1. fixtures 自动回归：断言每份夹具的告警码集合与 expected.json 一致，退出码非 0 即失败
node ~/.claude/skills/e2e-test-process/references/fixtures/run.mjs

# 2. 真实报告：新告警必须清零，旧报告（无 flow）告警输出与改造前逐行一致
node ~/.claude/skills/e2e-test-process/references/render-report.mjs <报告目录> --strict
```

新增夹具时同时登记到 `fixtures/expected.json`，并确保 `label` 覆盖短中文短语与长 URL / 长英文词两类排版边界。
