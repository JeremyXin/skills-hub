# 环境档案（profile）规范

> 公共层只规定**档案的位置、字段契约、建档流程与回写规则**；环境事实的具体值由被测仓库的 `.claude/auto-test-profile.md` 提供，取值方式（探测命令、查询通道）由项目级 skill 的「执行载体声明」给出。
> **档案不记录写通道、写数据源、业务开关取值、消息中间件取证策略**——这些在每次执行开始时由用户选定，或从运行时日志与行为判断。

## 1. 位置与加载

| 场景 | 读哪份档案 |
|---|---|
| 当前目录是被测仓库 | `<repo>/.claude/auto-test-profile.md` |
| 跨仓库链路 | 主仓库 profile + 关联仓库 profile（路径写在主 profile「跨仓库关联」） |
| 当前目录不是被测仓库 | 先问用户仓库路径，再从该路径读取 |

规则：

- 档案**按仓库一份**，只写本仓库的事实；跨仓库关联只记「对方仓库路径 + 关联点」，不复制对方内容；
- 档案与本文示例冲突时，以档案为准；
- 档案缺失的字段用 `<profile:key>` 标记，向用户询问后再使用，不猜。

## 2. 占位符约定

公共文档中的环境值统一写成 `<profile:字段名>`。**字段名只用下表列出的 key，不另行发明；档案模板的「项」列即对应 key。**

| key | 档案章节 | 说明 |
|---|---|---|
| `env` | §2 | 环境名（test / dev / 其他） |
| `app` | §2 | 应用名 / 容器服务名 / 进程名 |
| `deploy` | §2 | 部署标识；本地启动等无部署概念时填「不适用」 |
| `log.dir` | §2 | 业务日志目录（点号，不是 `log-dir`） |
| `domain.<标识>` | §3 | 每个访问入口一行；`domain.biz` 为主入口，其余用 `domain.<标识>`（如 `domain.upstream`），标识建档时与用户确认 |
| `read.channel` | §4 | 只读通道形态（数据库客户端、查询接口、命令行工具） |
| `read.command` | §4 | 只读查询的实际命令模板（不含密码） |
| `read.datasource` | §4 | 默认只读数据源；目标表在另一个可直连数据源时在 §4 加行 |
| `read.schema` | §4 | 全限定名前缀 |
| `test.phone-range` / `test.cleanup` | §5 | 测试数据约定，可选；不填时用 `test-data-spec.md` 的默认值 |

示例：

```
<profile:app>              → cf-leads-dataflow-v3-35
<profile:read.datasource>  → doris_wmt
<profile:domain.biz>       → https://xxx.example.com
```

读取失败时：先按 §3.2 推断；推断不出再问用户，拿到值后回写档案，再继续执行。

**每次执行开始时另需确定两项，但不写入档案**：

1. 数据写入与清理通道（`sql-query` / 测试接口 / 项目声明的其他形态）；
2. 触发入口（从 §3 的 `domain.*` 与接口文档确认）。

业务开关状态、消息中间件取证方式不在此阶段询问。

## 3. 首次建档：先问 2 件事，其余自己推断

原则：**不把收集清单变成提问清单**。只有必须由人决定的信息才问；能推断的跑命令或读代码得到，最后一次性确认整份档案。

### 3.1 必须先问的两件事

| 信息 | 为什么必须问 | 落点 |
|---|---|---|
| 业务入口地址 | 测试域名通常不在接口文档或代码里 | §3 `domain.biz` |
| 只读通道与数据源 | 取证必需；通道形态可推断，但**数据源名与库名无法安全推断**，猜错会查错库 | §4 `read.*` |

测试数据约定（号段、文本前缀、清理方式）有默认值，用户没特别要求就用默认。

### 3.2 其余信息：自动推断

按项目级 skill 声明的载体探测方式、仓库配置与代码得到，不打断用户；推断结果在 3.3 一并确认。

| 信息 | 推断来源 |
|---|---|
| 仓库路径、默认分支 | `git rev-parse --show-toplevel`、`git branch --show-current` |
| 环境名 | 项目 skill 的载体声明；默认 test |
| 应用名 / 部署名 / 日志目录 / 运行 profile | 项目 skill 声明的探测命令 + 仓库内的启动配置文件（不复制连接串） |
| 健康检查路径 | 启动配置或部署配置 |
| 只读通道形态 | 项目已安装的查询工具 + 应用的配置文件名（不含密码） |
| 不可直连的库及替代查询接口 | 代码中的数据源注解 / mapper 划分；接口文档 |
| 常用表（可选） | 本次需求相关的 mapper、migration 脚本；不预登记全量 |
| 跨仓库关联 | 代码中的 HTTP 客户端、消息 topic 的消费方 |

推断不确定的字段先标 `<profile:key>` 待补，不阻塞蓝图与用例设计；执行到依赖该字段的步骤前必须补齐。

### 3.3 一次确认

把 3.1 的回答与 3.2 的推断结果按 §4 模板组装成完整档案，**一次性**展示给用户；确认后写入。推断值与用户提供的值冲突时以用户为准，并说明差异。

## 4. 档案模板

文件：`<repo>/.claude/auto-test-profile.md`

> 代码块内的章节号（§1 仓库 … §7 已知限制）是**档案文件自身**的结构；其他文档中写作「档案 §4.1」的即指这里。

```markdown
# 自动化测试环境档案：<仓库名>

> 维护者：<项目级 E2E skill 名>，最后更新：YYYY-MM-DD。
> 只记录名称与地址，**禁止写入密码、AK、连接串**。

## 1. 仓库

| 项 | 值 |
|---|---|
| 仓库路径 | <绝对路径或相对主仓库路径> |
| 默认分支 | <branch> |

## 2. 运行与日志

| 项 | 值 | 来源 |
|---|---|---|
| 环境名 | <env> | <项目 skill 声明的探测方式> |
| 应用名 | <app> | |
| 部署标识 | <deploy> | 本地启动填「不适用」 |
| 日志目录 | <log.dir> | |
| 业务日志文件 | <文件名> | 实测 |
| 运行 profile | <profile> | |

## 3. 访问入口

> 「名称」列即 `<profile:domain.<标识>>` 的标识；`biz` 为主入口。

| 名称 | 地址 | 用途 |
|---|---|---|
| biz | https://... | 业务接口 |
| upstream | https://... | 上游服务（可选，按需增行） |
| 健康检查 | /health/check | 前置检查 |

## 4. 只读数据访问

| 项 | 值 | 说明 |
|---|---|---|
| 只读通道 | <read.channel> | 写清实际命令形态（不写密码） |
| 只读数据源 | <read.datasource> | |
| 只读库 | <schema/catalog> | 全限定名的前缀 |
| 只读命令 | <read.command> | 不写密码 |
| 可直连库 | <库名> | |
| 不可直连库 | <库名> | 只能走应用接口 |

### 4.1 常用表

可选章节：只登记反复用到的表；不预列全量。执行时按代码、接口与需求定位表名，权限按需申请（只读账号无表权限时先确认能否加授权，不要换账号重试）。

| 表 | 用途 | 归属 |
|---|---|---|
| <table> | | <数据源> |

### 4.2 替代查询接口

| 接口 | 数据 | 参数 |
|---|---|---|
| GET /xxx | | |

§4「不可直连库」非空时本节必填：这类库只能走应用接口，接口路径无从猜测；未登记的，依赖它的步骤记 BLOCKED。

## 5. 测试数据约定

| 项 | 值 |
|---|---|
| 测试号段 | <如 8613800000xxx> |
| 文本前缀 | AUTOTEST_ / 测试_ |
| 默认清理方式 | <接口或 SQL>；不填时按 test-data-spec.md §7 默认流程 |

## 6. 跨仓库关联

| 关联仓库 | 路径 | 关联点 |
|---|---|---|
| <repo> | <path> | <接口 / 消息流向> |

执行到对方服务时加载对方仓库的 profile，其 `app` / `log.dir` / `domain.*` 从那份档案取。**只写关系不写 topic 名**——topic 从代码常量与启动日志确认。

## 7. 已知限制

- <如：某库不可直连；某开关仅启动时读取>
```

字段可按需增删，但 §1–§4 不可缺；§5 可省略。**不要往档案里加写数据源、开关取值、消息 topic 之类随执行变化的内容。**

## 5. 回写规则

| 时机 | 动作 |
|---|---|
| 首次建档 | 展示完整内容 → 用户确认 → 写入 |
| 会话中用户口头给出新值 | 直接使用，并在回复末尾说明「已回写 profile：`<字段>`」 |
| 实测或读代码得到的值（如部署标识变化） | 与档案不一致时以实测/代码为准，**回写前先告知**；用户否认则保留原值并记录冲突 |
| 冲突未解决 | 该值视为不确定：涉及它的步骤记 BLOCKED，不得用任一版本的值继续 |
| 需求结束（兜底） | 检查本次新发现的表、查询接口是否已回写；漏掉的此时补上 |

回写时只改对应行，不重写整个文件，不删除用户手工补充的内容。

**环境变更后的复核**：环境重建、重新部署或切换环境后，依次确认版本、运行 profile 与日志路径、健康检查可达；有变化按本节回写，并把变化前后记进本次报告的「环境基线」。

## 6. 安全约束

| 禁止写入档案 | 原因 |
|---|---|
| 数据库密码、AK/SK、Token | 档案会提交进仓库 |
| 完整连接串（含 host/user/password） | 同上 |
| 真实用户号码、真实商家 ID | 隐私与误触达风险 |

需要这些值时的处理：从应用配置或环境变量读取，不落档案、不打印到日志。

## 7. 常见问题

| 问题 | 处理 |
|---|---|
| 档案里的部署标识过期 | 以项目 skill 声明的探测方式实测为准，回写前告知用户 |
| 同一仓库有多个测试部署 | 在 §2 加一行，按需求选择，不覆盖旧行 |
| 用户只提供只读通道 | 不阻塞建档；执行时若需构造数据，再问写入通道 |
| 用户不知道可写数据源/库 | 执行时改用测试接口，或生成 SQL 脚本交用户执行，不阻塞测试设计 |
| 跨仓库只知其一 | 先按已知仓库建档，关联仓库路径标 TODO，执行到该段时再补 |
| 关联仓库档案仍是 TODO 就执行到该段 | 依赖值缺失，该段用例记 BLOCKED，不猜对方仓库的值 |
| 档案与代码不一致 | 先确认是否切了分支/环境；结论写进报告「环境基线」，不静默采用 |
